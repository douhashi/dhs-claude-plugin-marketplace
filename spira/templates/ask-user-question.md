# テンプレート: 承認・選択の問い（AskUserQuestion）

- **書き手**: create-issue / sync-roadmap / mockup / architect / brainstorming / explain スキル
- **用途**: ユーザーの承認・選択を待つ箇所で、`AskUserQuestion` ツールに載せる問いの共通規則
- **各スキルの問い**: 問いの文・選択肢・回答ごとの行動は、各スキルのテンプレートの「問い」の節が定める。この文書はその前提となる規則だけを定める

## なぜ AskUserQuestion で聞くか

本文のテキストで承認を求めてターンを終えると、Orca はそれを `Stop` として受けて `done` と表示し、返事待ちと作業の終わりを区別できない。
`AskUserQuestion` の呼び出しは `waiting`（Needs You）として表示される。Orca の外でも同じく `AskUserQuestion` で聞く（`ORCA_PANE_KEY` の有無で聞き方を変えない）。

## 出し方

1. **判断材料を先に本文へ出す**。承認・選択の対象（表・提案・URL・変更のあるファイルなど）を、`AskUserQuestion` を呼ぶ前のテキスト出力として書く
2. 本文の最後に承認や選択を求める文を書かず、続けて `AskUserQuestion` を呼ぶ
3. 回答を受け取ったら、各スキルの「問い」の節の表に従って行動する

### 判断材料を出さずに呼ばない

`AskUserQuestion` のダイアログには `question` と `options` しか出ない。ユーザーはその直前の本文だけを見て判断する。
本文に判断材料が無いまま呼ぶと、ユーザーは「この順序」「この内容」が何を指すのか分からないまま答えることになる。

- **本文に判断材料を出していない応答で `AskUserQuestion` を呼ぶことは禁止**。思考の中や、ツールの結果の中にあるだけでは「出した」ことにならない
- 呼ぶ前に確かめる: `question` が指す対象（「この順序」「この内容」「この案」）が、この応答の本文に実際に書かれているか。書かれていなければ、先に書く
- 前の応答で出した表でも、修正を反映して聞き直すときは、反映後の表を本文に出し直してから呼ぶ
- 選択肢の中身（案の違い・根拠）は本文に書く。`options` の `description` は 1 文しか入らず、判断材料の代わりにならない
- 判断材料が要らない問いは無い。不明点の質問でも、何が分からず、なぜ答えが要るのかを本文に 1〜2 文で書いてから呼ぶ

この規則は `PreToolUse` フック（`${CLAUDE_PLUGIN_ROOT}/scripts/check-ask-material.sh`）が強制する。直前（別のツール呼び出しかユーザーの発言より後）に本文のテキストが無い呼び出しは拒否される。拒否されたら、判断材料を本文に書いてから同じ問いで呼び直す。

## 問いの規則

| 項目 | 規則 |
|:--|:--|
| 1 回の呼び出し | 問いは 1〜4 問。5 問以上になるなら、4 問ずつ続けて呼ぶ |
| `question` | 何を決めてほしいかを 1 文。表・提案の中身は本文に出し、`question` には書き写さない |
| `header` | 12 字以内（例: `起票`・`#27`・`方向性`） |
| `options` | 2〜4 択。`label` は 15 字以内、`description` は選んだら何が起きるかを 1 文 |
| 推奨 | 推奨がある問いは、推奨の選択肢を先頭に置き、`label` の末尾に `（推奨）` を付ける |
| `multiSelect` | 複数を選べる問い（例: 描く画面）だけ `true`。承認の問いは `false` |

- **「その他」「修正する」の選択肢を作らない**。`AskUserQuestion` には自由記述の `Other` が自動で付く
- **`Other` の自由記述は修正指示として扱う**。各スキルの「問い」の節で、`Other` の行は既存の修正指示の扱い（表の作り直し・再提示など）を指す
- 選択肢が「承認」しか立たない確認では、2 つ目に取りやめる行動（`見送る`・`ここで終える` など）を置く

## スキル共通の問い

複数のスキルで同じ形になる問いは、ここで定める。

### 未コミットの変更の確認（最新化の Phase）

最新化の前に `git status` で未コミット（brainstorming は未 push も）の変更を見つけたら、状況（変更のあるファイル）を本文に出し、次の問いを出す。

| 項目 | 内容 |
|:--|:--|
| `question` | 未コミットの変更があるため最新化できません。どうしますか |
| `header` | `未コミット` |
| `options` | `最新化せず続ける`（最新化を飛ばして次の Phase へ進む） / `ここで終える`（スキルを終える） |

| ユーザーの応答 | 行動 |
|:--|:--|
| `最新化せず続ける` | 最新化を飛ばして次の Phase へ進む |
| `ここで終える` | 以降の Phase を実行せずに終える |
| `Other`: 具体的な指示（stash・コミットなど） | 指示どおりに作業ツリーを整え、最新化からやり直す |

指示が無いまま stash・破棄をしない。

## 回答が得られないとき

- 回答が空のときは承認とみなさず、同じ問いを `AskUserQuestion` でもう一度出す
- ユーザーが問いを閉じた（呼び出しを拒否した）ときは先へ進まず、ユーザーの指示を待つ
- 回答を推測して先へ進まない
