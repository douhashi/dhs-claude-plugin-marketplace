# テンプレート: Issue 本文

- **書き手**: create-issue スキル
- **上限**: 1,500 字
- **共通ルール**: [_rules.md](./_rules.md)

以下のコードブロックの中身をそのまま雛形として使う。`（）` の指示に従って埋め、指示文自体は残さない。

```markdown
## 背景

（なぜこの要求が必要か。現状の課題を 2-3 文で。実装方針は書かない）

## 要求

（実現すべきことを「何を」の粒度で。1 項目 1 文）

- [ ] （要求）
- [ ] （要求）

## やらないこと

（この Issue のスコープ外を 1 項目 1 文。なければセクションごと省略する）

- （やらないこと）

## 受け入れ基準

（この要求が満たされたとみなす条件。1 項目 1 文。テスト観点もここに含める）

- [ ] （基準）
- [ ] （基準）

## 制約・前提

（制約事項・前提条件を 1 項目 1 文。なければセクションごと省略する）

- （制約）
```

## 注意

- 「どう実装するか」は書かない。設計は planner の仕事
- 「やらないこと」は、要求から自然に読み取れる範囲を超えて誤解されうるものだけを書く。自明な除外は書かない
- 「やらないこと」に挙げた項目のうち別途対応が必要なものは、フラットな別 Issue として起票する
- 関心事が複数あるなら Issue を分割する。1 Issue に詰め込んで字数を超えさせない
- 分割する場合も親子構造を作らない。関連 Issue は本文中で `#123` と参照するに留める
