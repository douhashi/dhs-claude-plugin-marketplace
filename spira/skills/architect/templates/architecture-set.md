# テンプレート: アーキテクチャセット

- **書き手**: `sets/` のセットを追加・更新する人
- **用途**: プロダクトの種類ごとに、構成を決めるときの叩き台を 1 ファイルにまとめる
- **上限**: 1 ファイル 150 行
- セットは参考情報である。同梱の内容は叩き台であり、最新かどうかは architect スキルの実行時に調査で確かめる

## 雛形

以下のコードブロックの中身をそのまま雛形として使う。見出しは 6 つとも省かない。

```markdown
# アーキテクチャセット: <プロダクトの種類>

同梱の内容は叩き台であり、最新かどうかは architect スキルの実行時に調査で確かめる。

## 対象と対象外

- 対象: （このセットで扱うプロダクトを 1 文）
- 対象外: （扱わないものを 1 文。別セットがあればそのファイル名）
- 責務: （このセットがどこまでを受け持つかを 1 文）
```

## 要件項目

「選定の観点」の要件列には、次の要件項目を必ず含める。

| セット | 要件項目 |
|:--|:--|
| 全セット | 想定規模 / AI エージェントが扱いやすいか |
| Web / API | 長時間ジョブキューの有無 / 独自ツール・ネイティブ依存の有無（例: ffmpeg, ヘッドレスブラウザ） |
| デスクトップ / モバイル | オフライン動作の要否 |

## 記述ルール

- 選定の観点は「要件 X なら Y を優先」の条件の形で書く。条件の無い好みは書かない
- 1 項目 1 文。書く内容は判断に要る最小限にする
- バージョン番号を書かない。版の確認は architect スキルの調査で行う
- 最終検証日は、推奨スタック例を公式ドキュメントで確かめた日付にする
- 導入手順・コード例・立ち上げタスクの雛形を書かない
- 用語はリポジトリと各技術の公式ドキュメントにある語を使い、独自の略語・造語・比喩を使わない
- Web / API の配布先は `_deploy.md` を参照させ、判定を各セットに書き写さない
