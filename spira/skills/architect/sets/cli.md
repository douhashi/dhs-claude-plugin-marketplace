# アーキテクチャセット: CLI

同梱の内容は叩き台であり、最新かどうかは architect スキルの実行時に調査で確かめる。

## 対象と対象外

- 対象: 端末から実行するコマンドラインツール
- 対象外: サーバーとして動く API（`api.md`）、画面を持つデスクトップアプリ（`desktop.md`）
- 責務: 各 OS 向けのバイナリを GitHub Release に置くまで。パッケージマネージャへの登録は対象外

## 構成パターン

| パターン | 使う場面 |
|:--|:--|
| 1 バイナリ（Go） | 既定 |
| 1 バイナリ（Rust） | Tauri とのコード共有や厳しい性能要件がある |
| API のクライアント | 同じ案件の API セットを呼ぶ |

## 選定の観点

| 要件 | 優先するもの |
|:--|:--|
| 特別な要件が無いなら | Go の 1 バイナリ |
| 同じ案件のデスクトップアプリ（Tauri）とコードを共有するなら | Rust |
| 厳しい性能要件（メモリ・起動時間・処理速度）があるなら | Rust |
| 想定規模が小さく配布先が少ないなら | Go のクロスコンパイルで各 OS 向けに出す |
| 同じ案件に API セットがあるなら | 認証と API 仕様は API セットに従う |
| AI エージェントに実装させるなら | 書き方の幅が狭く、ビルドが速い Go を優先する |

## 推奨スタック例

| 役割 | 推奨 | 理由 |
|:--|:--|:--|
| 言語 | Go | 依存の無い 1 バイナリを各 OS 向けに作りやすい |
| リリース | GoReleaser | 各 OS 向けのビルドと GitHub Release への配置をまとめて行える |
| CI | GitHub Actions | タグを契機に GitHub Release まで流せる |
