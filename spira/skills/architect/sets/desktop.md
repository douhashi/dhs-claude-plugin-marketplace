# アーキテクチャセット: デスクトップ

同梱の内容は叩き台であり、最新かどうかは architect スキルの実行時に調査で確かめる。

## 対象と対象外

- 対象: Windows / macOS / Linux で動くデスクトップアプリ
- 対象外: ブラウザで使う Web アプリケーション（`web.md`）、モバイルアプリ（`mobile.md`）
- 責務: 各 OS 向けのインストーラーを GitHub Release に置くまで。ストア配布（署名・審査）は対象外

## 構成パターン

| パターン | 使う場面 |
|:--|:--|
| Tauri + Web のフロントエンド | 既定 |
| Flutter のデスクトップ | 同じ案件にモバイルアプリがある |
| Tauri + API のクライアント | 同じ案件の API セットを呼ぶ |

## 選定の観点

| 要件 | 優先するもの |
|:--|:--|
| 特別な要件が無いなら | Tauri |
| 同じ案件に Web アプリケーションがあるなら | フロントエンドを Web セットに揃え、画面のコードを共有する |
| Web セットのフレームワークを Tauri で使うなら | Tauri は SSR を持たないため静的出力で使う |
| 同じ案件にモバイルアプリがあるなら | Flutter に寄せ、デスクトップとモバイルのコードを共有する |
| Tauri でモバイルも作りたいなら | Tauri のモバイル対応の成熟度を調査で確かめてから決める |
| オフライン動作が必要なら | データをローカルに持ち、同期は API セットで扱う |
| オフライン動作が不要なら | データは API セットに持たせ、アプリはクライアントにする |
| 想定規模が小さく配布先が限られるなら | 対象 OS を絞ってビルドする |
| AI エージェントに実装させるなら | 画面を Web の技術で書ける Tauri を優先する |

## 推奨スタック例

| 役割 | 推奨 | 理由 |
|:--|:--|:--|
| アプリの枠組み | Tauri | OS の WebView を使うため配布物が小さい |
| フロントエンド | Web セットと同じもの | 同じ案件で画面の書き方を揃えられる |
| ネイティブ処理 | Rust | Tauri のバックエンドが Rust であり、CLI セットの Rust とも共有できる |
| リリース | GitHub Actions | 各 OS 向けのビルドと GitHub Release への配置を行える |
