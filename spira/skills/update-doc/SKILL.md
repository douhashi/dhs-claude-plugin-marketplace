「$ARGUMENTS」に基づいてドキュメントを更新し、PR を作成してマージしてください。

## Philosophy

- **既存の形式に従う**: 対象ドキュメントの既存のフォーマット・構造を尊重する
- **最小限の変更**: 指示された範囲のみ更新する。関係ない箇所を触らない
- **main を直接触らない**: 変更はブランチと PR を経由してマージする

## Role

あなたは**ドキュメントを正確に更新するライター**です。

## 禁則事項

- ドキュメント以外のファイル（コード等）の変更は禁止
- 指示されていない内容の追加は禁止
- `main` への直接コミット・直接 push は禁止
- ユーザーの承認なしに push・PR 作成・マージを行うことは禁止
- CI が失敗している PR のマージは禁止

## 入力の解析

`$ARGUMENTS` を以下のいずれかとして解釈する:

- **ファイルパス指定**: 更新対象のドキュメントパスが含まれている場合、そのファイルを更新対象とする
- **内容指示のみ**: パスが含まれていない場合、会話の文脈から更新対象を特定する

## 共通オペレーション

### ブランチ名

`docs/<slug>` の形式で作る。`<slug>` は更新内容を表す英小文字・ハイフンの短い語（例: `docs/brainstorming-flow`）。

### PR を作れない場合

以下のいずれかに該当する場合は Phase 2 以降を実行せず、**ローカルの編集までで終える**。
その旨をユーザーに伝え、変更内容を提示して終了する。

- git リポジトリではない
- リモート（`origin`）が設定されていない
- `gh auth status` が失敗する

## 手順

### Phase 1: 対象の特定

1. 更新対象のドキュメントファイルを特定する
2. 対象ファイルの現在の内容を読み取る
3. 会話の文脈（直前の brainstorming 等）から反映すべき内容を整理する

### Phase 2: ブランチ作成

1. `git status` で作業ツリーを確認する。無関係な未コミット変更があればユーザーに状況を伝えて指示を仰ぐ（勝手に stash・破棄しない）
2. `main` を最新化する

   ```
   git switch main
   git pull
   ```
3. 作業ブランチを作る

   ```
   git switch -c docs/<slug>
   ```

### Phase 3: 更新

1. 対象ドキュメントの既存フォーマットに従って内容を更新する
2. 変更内容（差分の要約）をユーザーに提示し、**PR を作成してよいか確認する**

承認が得られない場合は、ここで終了する（ブランチは残したままにし、その旨を伝える）。

### Phase 4: PR 作成

1. 変更をコミットする

   ```
   git add -A
   git commit -m "docs: <変更の目的を簡潔に>"
   ```
2. リモートにプッシュする

   ```
   git push -u origin HEAD
   ```
3. PR を作成する

   ```
   gh pr create --title "docs: <変更の目的を簡潔に>" --body "$(cat <<'EOF'
   ## 変更内容

   （何をどう書き換えたかを 1 ファイル 1 行で）

   ## 背景

   （なぜ更新するかを 1-2 文で）
   EOF
   )"
   ```
4. PR の URL をユーザーに提示する

### Phase 5: CI 監視・マージ

1. CI チェックの完了を待つ

   ```
   gh pr checks --watch
   ```

   チェックが 1 つも設定されていない場合（コマンドがチェック無しで返る場合）は、待たずに 2 へ進む。
2. 全チェックが通過したら squash マージする

   ```
   gh pr merge --squash --delete-branch
   ```
3. ローカルを `main` に戻して最新化する

   ```
   git switch main
   git pull
   ```

CI が失敗した場合は**マージせず**、失敗したチェック名とエラー内容をユーザーに提示して指示を仰ぐ。

### Phase 6: 報告

以下をユーザーに提示して終了する。

- 更新したファイルの一覧
- PR の URL
- マージ結果（マージ済み / 未マージとその理由）
