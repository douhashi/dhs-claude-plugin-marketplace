# テンプレート: モックアップの提案

- **書き手**: mockup スキル（Phase 5 で方向性の比較ページを、Phase 6 で提案ページを作って公開し、Phase 7 でチャットに提示する）
- **用途**: 画面のモックアップとデザインの判断を 1 つのアーティファクトにまとめ、それだけを見て承認・修正指示を出せるようにする
- **読み手**: ユーザー（プロダクトオーナー）

## 提案ページ

`.tmp/spira-mockup/proposal.html` に書き、画面のモックアップ（`.tmp/spira-mockup/screens/<slug>.html`）を
Artifact ツールの `files` で `screens/<slug>.html` として一緒に公開する。提案ページはモックアップを `<iframe src="screens/<slug>.html">` で埋め込む。

提案ページはプレゼンテーションとして作る。モックアップの見た目を主役にし、文章は判断と根拠に絞る。
ページ自体の見た目は `artifact-design` の規約に従い、モックアップの配色・書体を提案ページに持ち込まない（どこからがモックアップかを枠で分かるようにする）。

### 節（この順序）

| # | 節 | 内容 |
|:--|:--|:--|
| 1 | 表紙 | 提案の題（例: 「通知一覧のデザイン」）・対象の画面・対象デバイス・デザインシステムの扱い（既存に従う / 拡張する / コードから起こす / 新規に作る）・日付 |
| 2 | 要約 | この提案で決めてほしいことを 3 行以内。`spira:request` から呼ばれた場合は、元のフィードバックの観点を添える |
| 3 | 画面 | 画面ごとに 1 ブロック（下記「画面のブロック」） |
| 4 | デザインの判断 | 観点ごとの決定と根拠の表（下記） |
| 5 | デザインシステム | 新規・コードから起こす・拡張のときだけ。トークン（色見本・書体の尺度・余白の尺度・動きの時間とイージング）とコンポーネントを実物で並べる。コードから起こした場合は抜き出し元のファイルを添える。拡張では追加・変更したものに `NEW` / `CHANGED` の印を付ける |
| 6 | 動き | 動きを新規に決めた・変えたときだけ。パターンごとに実物を再生ボタンで繰り返し見られるようにし、きっかけ・時間・イージングを添える |
| 7 | 反映するファイル | 承認後に作成・更新するファイルの一覧（新規 / 更新） |
| 8 | 確認したいこと | 決めきれなかった点を選択肢付きで。無ければ節ごと省く |

該当しない節（5・6・8）は見出しごと省く。

### 画面のブロック

- 画面名と、その画面で利用者が何をするかを 1 文
- モックアップの埋め込み。対象デバイスが両方ならデスクトップ（1280px）とモバイル（390px）の幅を切り替えられるようにする
- 状態（通常・空・読み込み中・エラー）の切り替え。モックアップ側の状態の切り替えと連動させるか、状態ごとに並べる
- 既存の画面を変える場合は、現状（既存のモックアップか既存の画面のスクリーンショット）と提案を左右に並べる。現状を見せられなければ、変わる点を箇条書きで示す
- 画面の要素と根拠の表

  | 要素 | 根拠 |
  |:--|:--|
  | （表示する情報・操作を 1 文） | `docs/concept.md:12`「（該当箇所の引用）」 |

### デザインの判断の表

| 観点 | 決定 | 根拠 |
|:--|:--|:--|
| スタイル | （名前） | （デザインスキルの指針を 1 文） |
| 配色 | （primary / accent / 背景。色見本を添える） | （1 文） |
| 書体 | （見出し / 本文。実際の文字で見せる） | （1 文） |
| レイアウト | （1 文） | （1 文） |
| 動き | （1 文） | （1 文） |

既存のデザインシステムに従った観点は「決定」に `既存どおり` と書く。
デザインスキルが入っていない環境では、表の下に `デザインスキル未導入のため、指針は自分の知識で確かめた` と 1 行添える。

## 方向性の比較ページ

デザインシステムを新規に作るとき（SKILL.md の Phase 5）だけ作る。`.tmp/spira-mockup/directions.html` に書き、
案ごとの画面（`.tmp/spira-mockup/directions/<a|b|c>.html`）を `files` で `directions/<a|b|c>.html` として一緒に公開する。

| # | 節 | 内容 |
|:--|:--|:--|
| 1 | 表紙 | 「<プロダクト名> のデザインの方向性」・描いた画面・日付 |
| 2 | 比べ方 | 3 案とも同じ画面・同じ文言で描いたことと、選んだ案がデザインシステムの土台になることを 2 行以内 |
| 3 | 3 案の比較 | 3 案の画面の埋め込みを横に並べる（狭い幅では縦に積む）。各案に名前（スタイルの名前を借りる。例: 「A: Minimal Swiss」）を付ける |
| 4 | 案ごとの特徴 | 下表 |

| 観点 | A | B | C |
|:--|:--|:--|:--|
| スタイル | （名前） | （名前） | （名前） |
| 配色 | （色見本） | （色見本） | （色見本） |
| 書体 | （実際の文字で） | | |
| 角丸・余白 | （1 文） | | |
| 動きの性格 | （1 文。例: 短く控えめ） | | |
| 合うプロダクト | （デザインスキルの指針を 1 文） | | |

チャットには次だけを書く。

```markdown
## デザインの方向性

<比較ページの URL>

A・B・C のどれを土台にしますか。組み合わせ（例: A の配色で B の書体）でも構いません。
```

## チャットでの提示

提案ページを公開したら、チャットには次だけを書く。表や判断の説明をチャットに再掲しない。

```markdown
## モックアップの提案

<提案ページの URL>

- （要約の節と同じ内容を 3 行以内）

修正はチャットか、ページへのコメントで伝えてください。この提案でリポジトリに反映してよいですか。
```

修正後の再提示では、URL と「変えた点」を 3 行以内で書き、最後に同じ承認を求める文を置く。提案ページには変えた点を要約の節に 1 行で足す。

## 記述ルール

- 画面の要素の根拠は、コンセプトの文書の `path:line` と引用。`spira:request` から呼ばれた場合は `フィードバックの観点 #N` と調査結果の `path:line`
- 表のセルは 1 文。見た目の説明はモックアップに任せ、長い説明文を書かない
- 用語はリポジトリとデザインスキルの資料にある語を使い、独自の略語・造語・比喩を使わない
