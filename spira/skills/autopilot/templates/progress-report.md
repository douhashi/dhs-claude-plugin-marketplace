# テンプレート: 進捗レポート

- **書き手**: orchestrator エージェント（毎イテレーションの返答）
- **読み手**: ユーザー（メインセッションがそのまま表示する）
- 状態記号は [state.md](./state.md) の「記号」節に従う

## 書き方のルール

- **ぱっと見て分かる量に絞る**。載せるのは「今どう動いているか」「今回何が変わったか」「次に何が起きるか」だけ
- ライン表は常に L1〜L3 の 3 行を出す。空いているラインは `空き`
- タイトルは 20 字を超えたら末尾を `…` で切る
- 「今回の出来事」には前回のレポートから変わったことだけを書く。変化が無ければ節ごと出さない
- 経過時間は分単位（60 分以上は `1時間20分`）
- ログの引用・エラーの全文・Issue の本文は載せない。詳細は Issue URL で辿らせる
- 最終行は必ず `NEXT: wait|halt|done` の 1 行にする

## 走行中（`wait`）

```markdown
## 🔁 自走開発 #5

| ライン | Issue | 状態 | 経過 |
|:--|:--|:--|--:|
| L1 | #21 ログイン API を追加する | 🧪 CI | 42 分 |
| L2 | #24 通知設定を保存する | 🛠 実装 | 8 分 |
| L3 | — | 空き | — |

**全体** ✅ 3 · 🚧 2 · 残り 4 · ⛔ 0 · 🆘 0

**今回の出来事**
- ✅ #22 設定画面を追加する — マージ
- 🆕 #31 を取り込み（ログイン API が 500 を返す／ロードマップ: #25 の直前、PR #33 をマージ）
- 🆕 #32 は見送り（拡張のため今回は扱わない）
- 🆘 #34 は見送り（#21 の変更箇所に閉じた失敗のため継続）
- ▶️ #24 を L2 で開始

**次** ラインの完了を待ちます（最長 30 分）

NEXT: wait
```

- ループ中に見つかった Issue は 1 件 1 行で、判定と理由を 1 文で書く
- `全体` の 🚧 は走行中のライン数、`残り` は Open Issue のうち走行中でないもの
- `L3` が空いているのに起動しなかった場合は、`次` の行に理由を 1 文で添える（例: `#25 は #24 の完了待ち`）

## 人手待ちで停止（`halt`）

走行中のラインがすべて終わり、未解消のブロッカーか `停止理由` があるときに出す。

```markdown
## ⏸ 自走開発を止めました #9

**全体** ✅ 6 · 残り 3 · ⛔ 1

（ここに [blocker-guide.md](./blocker-guide.md) の「環境変数の設定」節か「エスカレーション」節を、orchestrator 用の再開方法で続ける）

NEXT: halt
```

## 終了（`done`）

走行中のラインが無く、`spira:pick` が着手できる Issue を返さないときに出す。

```markdown
## 🏁 自走開発が終わりました #12

| 結果 | 件数 |
|:--|--:|
| ✅ 完了 | 8 |
| ⚠️ 失敗 | 1 |
| 🆘 エスカレーション | 1 |

**残っている Issue**

| Issue | 理由 |
|:--|:--|
| #30 本番デプロイ手順を整える | 🆘 #31 で人手対応待ち |
| #27 検索を高速化する | ⚠️ 再試行でも完了せず |

NEXT: done
```

- 残っている Issue が無ければ `残っている Issue` の節は出さない
- 残っている Issue の理由は 1 文。失敗の詳細は書かず、必要なら Issue 番号で辿らせる
