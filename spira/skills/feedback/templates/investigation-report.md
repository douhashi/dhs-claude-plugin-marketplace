# テンプレート: フィードバック調査結果

- **書き手**: feedback スキル（Phase 4）
- **用途**: フィードバックの観点ごとに、調査で確かめた事実と対応を示す

## 雛形

以下のコードブロックの中身をそのまま雛形として使う。

```markdown
## フィードバック調査結果

| # | 観点 | 種別 | 調査結果 | 対応 |
|:--|:--|:--|:--|:--|
| 1 | 起票後にロードマップが更新されない | 不具合 | `create-issue/SKILL.md` に追記の手順が無い | 起票 |
| 2 | Issue の本文が長すぎる | 改善要望 | #18 で字数上限の見直しを扱っている | 既存 Issue（#18） |
| 3 | pick が escalated を先に選ぶ | 質問 | `pick/SKILL.md` の優先順どおり | 仕様どおり |

### 根拠

- **1**: `spira/skills/create-issue/SKILL.md:88` — 報告で終わり、ロードマップに触れていない
- **2**: #18 `refactor(spira): Issue 本文の上限を見直す`（Open）
- **3**: `spira/skills/pick/SKILL.md:52` — 優先順 1 が `escalated`

`起票` の 1 件を `spira:create-issue` で Issue 化します。
```

## 列

| 列 | 内容 | 上限 |
|:--|:--|--:|
| `#` | 通し番号 | — |
| 観点 | 困りごとを 1 文（書かれた解決策ではなく課題） | 30 字 |
| 種別 | `不具合` / `改善要望` / `質問` / `その他` | — |
| 調査結果 | 確かめた事実を 1 文。確かめられなければ `未確認: <理由>` | 40 字 |
| 対応 | `起票` / `既存 Issue（#N）` / `対応済み（#N）` / `仕様どおり` / `判断保留` | — |

## 記述ルール

- 「根拠」は観点ごとに 1 行。`path:line`・Issue 番号・PR 番号など、ユーザーが辿れる形で示す
- `質問` の観点は、表の後に回答を 3 行以内で書いてよい
- `判断保留` の観点は、「`spira:brainstorming` で議論する」ことを最後の 1 文に添える
- 最後の 1 文は次のいずれか
  - `起票` あり: `` `起票` の N 件を `spira:create-issue` で Issue 化します。 ``
  - `起票` なし: `起票が必要な観点はありません。`
- 表と根拠の外に、経緯や感想を書かない
