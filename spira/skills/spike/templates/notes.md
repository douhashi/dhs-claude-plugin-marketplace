# テンプレート: スパイクの作業メモ

- **書き手**: spike スキル（Phase 1 で先頭を、Phase 3・5・6・7 で各節の行を書く）
- **用途**: 問い・確かめたこと・発見・課題を控え、PR 本文と報告に載せてよいものの範囲を決める
- **読み手**: spike スキル自身（Phase 7・8）。ユーザーには見せない

`.tmp/spira-spike/<SLUG>/notes.md` に書く。

## 雛形

```markdown
# テーマ

<テーマを 1 文。Issue から始めたなら #N も添える>

# 問い

| # | 問い | 成功基準 | 答え |
|--:|:--|:--|:--|
| 1 | <動かせば答えが出る問い> | <観測できる事実> | <答え> |

- やらないこと: <問いに関係しない作り込み>

# 確認

| 問い | 確かめたこと | 出典 |
|--:|:--|:--|
| 1 | <動かして分かったこと> | `<実行したコマンド>` → `<結果の要点>` |
| 1 | <調査で分かったこと> | `<path>:<line>` または URL |

# 発見

- <問いとは別に気づいた事実>（`<path>:<line>`）

# 課題

- <本実装で解く必要があること。打ち切った問いなら、障害と試したこと>

# 近道

- <本実装では避けるべき近道>（`<path>:<line>`）
```

## 答えの定義

| 答え | 条件 |
|:--|:--|
| `実現可` | 成功基準を動かして確かめた |
| `条件付きで実現可` | 成功基準は満たしたが、前提（制約・追加の作業・外部の条件）が要る。条件を「課題」に書く |
| `実現不可` | 成功基準を満たせないことを、動かして、または仕様の明記で確かめた |
| `未確認` | 確かめられなかった。理由を「確認」に書く |

## 記述ルール

- 1 行 1 文。解釈や評価を混ぜず、確かめたことだけを書く
- 「確認」の出典は、実行ならコマンドと結果の要点、調査なら `path:line` か URL
- 空の節は「なし」と 1 行書く
